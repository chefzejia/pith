## 1. 双场景空间架构：首页统一立项台 vs 课题内五区工作台

Pith 的所有宿主壳（[`src/shells/obsidian/`](../../src/shells/obsidian/)、[`src/shells/web/`](../../src/shells/web/) 与 [`src/shells/dsh/`](../../src/shells/dsh/)）100% 共享同一份 `src/workbench/` 界面。为了避免首页与课题内入口打架，系统在空间上严格区分为 **「首页：课题看板与统一立项台」** 与 **「课题内：五区工作台」** 两个场景：

### 1.1 场景一：首页课题看板与极简无感立项台（`Compass & Omnibox Intake` · [`compass.ts`](../../src/workbench/compass.ts)）

首页不展开右侧聊天边栏（零视觉分裂），在页面中央顶部提供**仅含 `[ + ]`（支持拖拽）与单一提交箭头 `[ ↑ ]` 的极简无感立项框（Omnibox Intake）**，严禁堆砌“添加文件 + 绑定仓库 + 直接开启 + 请向导拆解”四个分裂按钮逼用户做分类选择：

```text
+---------------------------------------------------------------------------------------+
| Pith                                                                            [⚙]   |
+---------------------------------------------------------------------------------------+
| 课题看板                                                                              |
| ┌─ 极简无感立项台 (Omnibox Intake · 支持拖拽 / + 选文件 / 贴入本地仓库路径或 URL) ──┐ |
| │ [ + ]  输入想探索的课题、贴入本地 Git 仓库路径 / 视频链接，或直接拖入文件…   [ ↑ ]│ |
| └───────────────────────────────────────────────────────────────────────────────────┘ |
| ┌─ 下一步 · 15 分钟焦点 (Focus Recommendation) ─────────────────────────────────────┐ |
| │ 精读《01-核心拓扑.md》并用费曼工具复述 HostPort 边界              [ 继续探索 → ]  │ |
| └───────────────────────────────────────────────────────────────────────────────────┘ |
| 探索中 (N)  [ 带封面/工具标签/下一步建议/笔记计数的书卷卡片网格 .pith-topic-grid ]    |
| 已沉淀 (M)  [ 克制优雅的水平归档列表 .pith-settled-list ]                             |
+---------------------------------------------------------------------------------------+
```

- **后台 100% 自动嗅探与分流（Zero Classification Friction）**：
  1. **输入支持**：支持点击左侧 `[ + ]` 选择文件、直接将文件拖拽（Drag & Drop）至立项框，或在输入框中直接输入**课题意图**、**本地 Git 仓库绝对路径**（如 `/Users/me/Projects/dsh`）或**外部网页/视频链接**（`https://...`）；
  2. **自动判定逻辑（点击右侧 `[ ↑ ]` 或按 `Enter` 提交时由后台自动分流）**：
     - **情况 1（本地 Git 仓库路径）**：若输入的文本是本地路径（以 `/`、`~/` 或盘符开头）且无上传文件，自动作为 Git 仓库路径调用 `inspectRepository` 绑定为 `kind: "repo"` 材料，预挂载 `["feynman"]`，进入课题后**自动展开右侧向导并触发首轮渐进课程拆解**；
     - **情况 2（显式文件导入）**：若用户添加了文件（或拖入文件），自动按文件特征导入为 `Material` 并应用 `defaultToolkitsForMaterial` 预挂载默认工具。若用户仅导入文件未写额外问题，**零等待直接进入 Stage 阅读/听读（向导默认收起）**；若同时写了具体问题/拆解要求，则进入后自动展开向导回应；
     - **情况 3（一句话庞大课题或外部链接）**：若仅输入了课题意图或 URL，创建课题并进入工作台：当已配置向导 Agent 时，**自动展开右侧向导并启动渐进课程拆解（生成课程蓝图与第一讲）或调用语料工具抓取媒体**；当未配置向导 Agent 时，静默进入课题工作台（不报错阻断）。

### 1.2 场景二：课题内五区空间拓扑、渐进课程目录树与统一 SVG 图标系统（[`view.ts`](../../src/workbench/view.ts) & `icons.ts`）

1. **全仓统一线性 SVG 图标体系（`src/workbench/icons.ts` · 严禁 Emoji 与散装字符图标）**：
   - 全仓工作台（顶栏、立项框、目录抽屉、向导栏、播客甲板、选区悬浮条、原位跟读坞）统一使用 `24×24` viewBox、`stroke-width="1.75"`、`stroke-linecap="round"`、`stroke-linejoin="round"` 的单色线性 SVG 图标，严禁在按钮中混用 `🛠`、`🎧`、`🎙️`、`📁`、`✨`、`🔁`、`🔊` 等系统 Emoji 或散装符号。
2. **渐进式课程大纲与左侧目录抽屉（`.pith-left-drawer`）合二为一**：
   - 课程拆解是**按需渐进（Just-in-Time）**的：向导首轮规划《`00-课程大纲.md`》（其中列出如 `- [01-xxx.md] 第一讲标题`、`- [02-xxx.md] 第二讲标题` 的章节蓝图）并仅生成《第 01 讲》正文；
   - 左上角导航抽屉自动解析《`00-课程大纲.md`》中的课程章节规划，将其与材料文件列表融合渲染为统一的 **课程章节树（Curriculum Tree）**：
     - **已生成章节**：常规高亮可点，点击直接切换阅读；
     - **待生成章节（Planned Lesson）**：标记柔和的 `待生成` 徽标；**当用户直接点击任意尚未生成的后续章节时，Stage 立即显示该讲加载态并自动向向导发送生成该讲的指令（`请按课程大纲生成《0X-xxx.md》讲义`），生成落盘后自动在左侧 Stage 打开该讲**！
3. **右侧向导栏动作胶囊去重铁律（Zero Duplicate Action Buttons）**：
   - 当对话流最新一条向导回复已附带上下文动态选项胶囊（`pith-choices`）时，**严禁在下方同时堆叠渲染固定的 `guideData.actions` 按钮**（避免出现 4 个灰框按钮打架）；
   - `guideData.actions` 仅在尚无向导 `pith-choices` 时展示，且若课题下已生成《`00-课程大纲.md`》或已有可读讲义，自动隐藏过期的 `"规划课程大纲与第一讲"` 动作。

### 五区准入硬边界

1. **Zone 1（44px 极简顶栏）**：
   - 左侧依次为 `[☰ 目录与材料抽屉]`、`[‹ 返回课题看板]`、课题/章节标题；
   - 右侧依次为：分页器 `< 1/N >`（仅按屏分页书籍显示）、**工具槽按钮 `#open-dojo`**（已挂载 `Toolkit` 时显示当前工具名如 `🛠 影子跟读 ▾`，未挂载时显示低调 `🛠` 供用户随时点击开启/管理 `Toolkit`）、伴读开关 `🎧`、排版菜单 `Aa`、向导开关 `?`、补充材料 `+`、设置 `⚙`。
   - 点击 `[Aa]` 或 `#open-dojo` 时，轻量控制菜单紧贴顶栏右下方近源展开，**严禁跑到屏幕底部或左下角弹出**。
2. **Zone 2（主视觉舞台 Stage & 左侧目录抽屉）**：
   - 课题下多文件切换（如《`00-课程大纲.md`》、《`01-核心拓扑.md`》与原书）及章节目录树统一收纳在左侧滑出抽屉 `.pith-left-drawer` 中。
   - 框选非空正文时，选区上方弹出 `[ 高亮 | 记笔记 | 问向导 | 复制 ]` 四键悬浮条。
3. **Zone 3（内容正下方唯一准入区：`.pith-media-deck`）**：
   - **内容正下方区域唯独只有音频播放控制条（`.pith-media-deck`）允许进入**！当材料含音频或正在执行 TTS 伴读时，在 Flexbox 底部**实心停靠**（挤压上方阅读容器高度，零遮挡正文）。
4. **Zone 4（右侧向导栏 Guide & 纯净文本输入边界）**：
   - 普通阅读进入时默认收起（占 `0px`）；通过首页拆课立项进入或点击 `?` / `问向导` 时自动展开，并按 `topicId` 独立记忆开合状态。
   - **严禁内嵌通用“语音输入”按钮**：向导侧栏底部输入区（以及 `feynman` 等文本阐述框）仅保留文本输入框与发送按钮（用户若需语音打字可直接调用操作系统输入法）；**Pith 中的麦克风录制是一项专属的具身训练交互行为，仅内嵌于 `shadowing`（影子跟读）等声学实训 `Toolkit` 的原位声学坞中**！

## 2. `Toolkit` 的多点位空间注入矩阵（Multi-Slot Toolkit Protocol）

不同 `Toolkit` 按其 `UI Protocol` 分别投射到工作台的 **4 个挂载点**：

| 挂载槽位 | 1. 输入降噪 (`interline`) | 2. 程序性声学跟练 (`shadowing`) | 3. 生成式复述 (`feynman`) |
| :--- | :--- | :--- | :--- |
| **① 顶栏工具槽与 CRUD 菜单**<br>*(Top Bar & Toolkit Popover)* | 顶栏显示 `[🛠 行间双语]`；近源菜单支持切换 `[ 原文 \| 行间双语 \| 译文主显 ]` 及勾选增删课题工具 | 顶栏显示 `[🛠 影子跟读]`；近源菜单支持切换激活工具或勾选增删课题工具 | 顶栏显示 `[🛠 费曼复述]`；近源菜单支持开启当前段复述或勾选增删课题工具 |
| **② Stage 画布原位 `UI Protocol`**<br>*(In-Place Stage Overlay)* | **段落正下方内嵌译文行**：在每个 `[data-prose="true"]` 块内底部插入 `.pith-interline-subtitle[data-prose="false"]` | **目标句原位四阶镜头 + 专属声学闭环坞**：在 `.pith-cue` 或段落原位展开：1) `[ 韵律 \| 原文 \| 骨干 \| 盲听 ]`；2) **`[ 原声 ]`、`[ 循环 ]`**；3) 唯一麦克风入口 **`[ 开口跟读 ]`** + **`[ 回听对比 ]`** + 原位 `<mark>` 漏词标亮 | **目标段原位遮罩与阐述条**：在画布目标段落原位将其平滑折叠遮罩（“合上原文”），紧贴下方内联展开纯文本阐述框（无冗余语音输入按钮）及 `[提交复述并请向导追问]` |
| **③ 底部播客甲板联动**<br>*(Media Deck Sync)* | 译文块携带 `data-prose="false"`，甲板 TTS 伴读自动跳过译文 | 点击 `[▶ 播放本句]` / `[🔁 单句循环]` 自动驱动甲板音频定位到该句 `startSec..endSec`（或合成该句语音），录音时自动静音原声（`guided-follow` 边放边录除外） | 实训阐述与录音期间保持甲板音频静默 |
| **④ 右侧向导栏联动**<br>*(Guide Sidebar Integration)* | - | 向导快捷栏动态注入 `[分析跟读]` 胶囊；支持将漏词对齐记录一键存为 `practice` 笔记 | 向导快捷栏动态注入 `[费曼深水区追问]` 胶囊；提交复述后直接携带 `evaluationRubric` 发往右侧向导触发**三明治苏格拉底追问** |

## 3. 跨设备连续几何自适应与宿主主题继承

1. **连续几何自适应（[`resolveResponsiveLayout`](../../src/plugins/stage-reader/pagination.ts)）**：根据容器实时净宽、高宽比与指针类型动态切换向导栏形态（`"split-right"` / `"overlay-drawer"` / `"bottom-sheet"`）及最大可读栏数（1~3 栏）。
2. **100% 跟随宿主主题变量**：统一消费宿主 CSS 变量与明暗自适应语义色（探索态 `--pith-sage`、沉淀态 `--pith-clay`），严禁调用阻塞式 `window.alert()`。
