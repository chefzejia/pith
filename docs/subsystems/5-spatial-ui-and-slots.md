## 1. 三个场景

所有宿主壳（[`src/shells/obsidian/`](../../src/shells/obsidian/)、[`src/shells/web/`](../../src/shells/web/)、[`src/shells/dsh/`](../../src/shells/dsh/)）共用同一份 `src/workbench/` 界面。界面分三个场景：

| 场景 | 从哪里进入 | 有什么 | 没有什么 |
| :--- | :--- | :--- | :--- |
| **首页** | 启动、返回 | 立项框、今日下一步、课题、材料库 | 向导栏 |
| **材料阅读** | 在材料库打开一份材料，或投喂单份材料后 | 舞台、高亮与笔记、行间、伴读、「以此立项」 | 对话、训练工具 |
| **课题内** | 打开一个课题，或立项成功后 | 舞台、向导栏（对话与笔记）、训练工具、讲义与材料目录 | - |

全部场景统一使用 [`icons.ts`](../../src/workbench/icons.ts) 的线性 SVG 图标（`24×24` viewBox、`stroke-width="1.75"`、圆角端点），按钮里不出现 Emoji 或散装符号。下面示意图里的符号只是占位。

## 2. 首页（[`compass.ts`](../../src/workbench/compass.ts)）

```text
+-------------------------------------------------------------------------------+
| Pith                                                                    [设置] |
+-------------------------------------------------------------------------------+
| ┌─ 立项框 ──────────────────────────────────────────────────────────────────┐ |
| │ [+]  说出想搞懂的问题，或拖入文件、贴入链接与本地仓库路径…           [↑] │ |
| │ [已选材料的标签 ×]                                                       │ |
| │ （立项回合运行时：过程行逐行出现，[↑] 变成 [停止]）                      │ |
| └──────────────────────────────────────────────────────────────────────────┘ |
| ┌─ 下一步 · 15 分钟 ───────────────────────────────────────── [继续探索] ──┐ |
| 进行中 (N)   课题卡片：目标 · 材料数 · 训练工具 · 下一步 · 记录数      [⋯]   |
| 搁置 (K)     折叠列表，每行 [恢复]                                            |
| 已沉淀 (M)   列表                                                             |
| 材料库 (L)   材料卡片：封面 · 标题 · 类型 · 被几个课题引用 · 上次读到哪里     |
| 无法读取 (U) 账本路径与原因，只读；U 为 0 时不显示                            |
+-------------------------------------------------------------------------------+
```

### 2.1 立项框的分流

立项框只有 `[+]`（也接受拖拽）与一个提交按钮。提交时按输入内容分流，不让用户选类别：

| 提交的内容 | 结果 | 需要向导 |
| :--- | :--- | :--- |
| 只有文件 | 导入材料库 | 否 |
| 只有一个 `http(s)://` 链接 | 抓取并导入材料库 | 否 |
| 只有一个本地路径（以 `/`、`~/` 或盘符开头） | 作为 Git 仓库绑定当前提交，导入材料库 | 否 |
| 有一句话目标，可以同时带上述任意材料 | 材料先入库，然后立项 | 是 |

- **多个文件的分组**：去掉扩展名与语言后缀后同名的文件合成一份材料（音视频与它的字幕靠同名配对）；其余每个文件各成一份。
- **投喂之后**：恰好得到一份材料时直接进入材料阅读；多于一份时留在首页，材料库滚动到新增的条目。
- **路径后面的文字**：路径后跟一段说明时，说明就是目标，按最后一行处理。

### 2.2 立项

1. 带来的材料先导入材料库。这一步与向导无关，立项失败时材料仍在库里。
2. 调用 `engine.intake`。立项回合的过程行显示在立项框下方，提交按钮变成停止。
3. 结果有三种：
   - **课题已创建**：进入课题内场景，向导栏展开。
   - **向导先问了一个问题**（没有创建课题）：问题显示在立项框下方，你的回答连同此前的立项回合一起再次提交。
   - **失败或被你停止**：不留下课题，原输入回到立项框，原因显示在框下方。
4. 向导未连接时，带目标的提交不可用，框下方给出原因和设置入口。只投喂材料不受影响。

### 2.3 课题与材料库

- **课题卡片**：标题、目标、引用的材料数、训练工具、下一步、记录数。`[⋯]` 里只有「搁置」。搁置的课题不参与今日下一步，在折叠列表里按行显示，每行一个「恢复」。
- **材料库**：全部材料，按最近打开排序，默认显示前 12 份，可展开。每份显示被几个课题引用；没有被引用的不做特殊标记。
- **封面**：看板只读 `_cache/covers/` 里的缩略图，不读原始文件。缩略图在导入时生成，缺失时在后台补生成。

## 3. 材料阅读

```text
| [目录] [返回]  材料标题            ‹ 1/N ›   [伴读] [Aa]   [以此立项]   [笔记] |
+---------------------------------------------------------------+---------------+
| 舞台                                                          | 笔记 N        |
|   框选非空正文：[ 高亮 | 记笔记 | 复制 ]                      | （列表 + 输入）|
+---------------------------------------------------------------+---------------+
| 播放控制条 .pith-media-deck（有音频或伴读时）                                 |
```

- 高亮与笔记记在材料上（`capture` 的 `owner` 是这份材料）。以后这份材料被某个课题引用，向导能读到这些记录。
- 右侧栏只有笔记，没有对话；选区悬浮条没有「问向导」。
- 行间在 `[Aa]` 阅读菜单里（第 5 节）。
- **以此立项**：右侧栏换成一个输入框，问「你想通过这份材料搞懂什么」，提交即以这份材料发起立项（2.2），过程行显示在右侧栏。课题创建后进入课题内场景。

## 4. 课题内（[`view.ts`](../../src/workbench/view.ts)）

```text
+---------------------------------------------------------------------------------------+
| [Zone 1: 44px 顶栏]                                                                   |
| [目录] [返回]  课题标题 · 当前文件   ‹ 1/N ›  [训练工具 ▾] [伴读] [Aa] [向导] [+材料] |
+-----------------------------------------------------------+---------------------------+
| ▲ 点击 [目录] 从左侧滑出 .pith-left-drawer，              | [Zone 4: 向导栏]          |
| │ 平时收起占 0px，正文头顶不放文件标签条                  |  [ 对话 | 笔记 N ]        |
|                                                           |  对话回合 / 笔记列表      |
| [Zone 2: 舞台 (flex: 1)]                                  |  选项或快捷动作           |
|   书卷/讲义舞台 (stage-reader)                            |  [ 选区引用预览 ]         |
|   时间轴舞台 (stage-timeline)                             |  [ 输入框   发送/停止 ]   |
|                                                           |                           |
|   2a. 选区悬浮条：[ 高亮 | 记笔记 | 问向导 | 复制 ]       |                           |
|   2b. 工具原位覆盖层（行间 / 影子跟读 / 费曼复述）        |                           |
+-----------------------------------------------------------+---------------------------+
| [Zone 3: 播放控制条 .pith-media-deck]                                                 |
| [▶/⏸]  01:24 / 08:45  ━━━●━━━|━━━━|━━━━━━━  [↺15] [15↻] [1.0x] [跳回当前句] [✕]       |
+---------------------------------------------------------------------------------------+
```

### 4.1 Zone 1：顶栏

- 左侧：目录抽屉、返回首页、课题与当前文件标题。
- 右侧：分页器（只在按屏分页的书籍上显示）、训练工具按钮、伴读、阅读菜单 `[Aa]`、向导开关、添加材料、设置。
- **训练工具按钮**：挂了工具时显示当前工具名，没挂时显示图标。菜单里切换当前工具，勾选或取消已注册的训练工具。菜单里没有行间。
- **添加材料**：从材料库选、选文件、贴仓库路径或链接。新材料先入库再被本课题引用。课题不能移除已引用的材料。
- `[Aa]` 与训练工具的菜单紧贴顶栏右下方展开。收起方式一致：再点各自的按钮、按 `Esc`，或点菜单与按钮之外的区域。选段后的工具面板不随这些操作收起。

### 4.2 Zone 2：舞台与目录抽屉

目录抽屉分两组：

1. **讲义**：解析《`00-课程大纲.md`》里的章节规划，与已有讲义合并成章节树。已生成的可点；规划了但还没写的带「待生成」标记，点击后舞台显示加载态，并向向导发起一个生成该讲的回合，写入后自动打开。
2. **材料**：课题引用的每份材料一个分组，组内是它的文件与当前文件的目录树。仓库材料的分组列出绑定提交里的文件。

框选非空正文时，选区上方弹出 `[ 高亮 | 记笔记 | 问向导 | 复制 ]`。

### 4.3 Zone 3：播放控制条

- 内容正下方只允许 `.pith-media-deck` 进入，实心停靠，挤压阅读容器高度，不遮挡正文。
- 全系统只有这一个播放底座和一条进度条，音频、视频、TTS 伴读与影子跟读共用。正文里不放第二个原生播放器，没有手动 A-B 按钮。
- 音视频带时间轴字幕或语义切片时，进度条轨道上渲染切片刻度（`.pith-deck-slice`）；点击或拖到任意位置，舞台滚动并聚焦对应字幕，影子跟读开着时聚光灯切到该句。

### 4.4 Zone 4：向导栏

- 打开课题时默认收起；立项成功进入、点击向导开关或选区的「问向导」时展开，按课题记忆开合状态。
- 「笔记」页签的发送只落盘笔记，不发起回合。
- 输入区只有文本框与一个按钮，不放通用语音输入。麦克风只属于影子跟读的声学坞。
- 已沉淀的课题可以打开、阅读和查看对话，输入区不可用。

对话的显示规则在第 6 节。

## 6. 对话

行为与观感以 dsh 的对话界面为基准，只对齐行为，不引入它的代码。出处与实测记录在任务 #45 的对照清单里。下面是 Pith 的取值。

### 6.1 一个回合的组成

```text
                                              ┌───────────────────────┐
                                              │ 你的消息（右对齐气泡）│
                                              └───────────────────────┘
▸ 已完成 · 读了 3 个文件，写了 1 份讲义        ← 过程组，完成后折叠成一行
  （展开后）
  思考 ▸                                       ← 只在收到思考内容时出现，默认收起
  读取 packages/core/README.md
  写入讲义《01-内核边界.md》                   ← 可点：打开讲义
  记入画像：熟悉依赖注入…        [撤销]       ← 可点：撤销这条观察
向导的回复（Markdown）
[ 1. 选项 ] [ 2. 选项 ]                        ← 只在最新一个回合显示
```

- **过程行**：相邻的思考与工具步骤归为一组。工具行显示动作与对象（文件名、讲义名），运行中、完成、失败三种状态。不识别的工具显示原名。
- **回复**：在过程组之外，始终可见。一个回合里的多段回复都保留，按到达顺序排列。
- **折叠**：回合成功结束后，过程组折叠成一行摘要，可以再展开。失败或被停止的回合不折叠。只有这一种显示方式，没有详略模式的设置。
- **可点的结果**：讲义行打开讲义；笔记行跳到原文；材料行打开材料；画像行显示新增的那句话并带撤销。撤销调用 `removeObservation`。
- **选项与快捷动作**：最新回合带选项时显示选项；否则显示快捷动作。两者不同时出现。点击选项即以它为消息发起下一个回合。

### 6.2 运行中

- 你的消息立刻出现。过程组显示当前阶段（「等待向导回应」，收到工具调用后是具体动作）与已用时间。已用时间从请求发出算起。
- 按钮从「发送」变成「停止」。输入框保持可编辑，草稿保留；运行期间不能发第二条，也不排队。
- 不显示重试次数、剩余秒数或逐字速度这类 Pith 拿不到的信息。

### 6.3 结束

| 结束状态 | 显示 |
| :--- | :--- |
| 完成 | 过程组折叠，回复与选项可见 |
| 失败 | 你的消息保留；过程组保持展开；下面一行失败记录，写明原始原因，带「重新请求」 |
| 被停止 | 你的消息保留；已收到的步骤和回复保留；一行「已停止」，带「重新请求」 |

「重新请求」用同一条消息再跑一次，替换这个回合，不产生第二条你的消息。失败原因留在对话里，不随下一个回合消失。

### 6.4 输入

- `Enter` 发送，`Shift+Enter` 换行；输入法组字期间的 `Enter` 不发送。
- 回合运行中 `Enter` 不起作用。停止只通过按钮。

### 6.5 Markdown 与滚动

- 回复用讲义同一个渲染器（[`renderMarkdown`](../../src/plugins/stage-reader/index.ts)）：标题、段落、粗体、行内代码、代码块、有序与无序列表、引用、表格（可横向滚动）、`http(s)` 链接。原始 HTML 不作为标记渲染；其余协议的链接显示为文本。
- 每条回复带「复制」，复制的是 Markdown 原文。
- **跟随**：视口在底部附近时，新内容到达自动跟随；你向上滚动后停止跟随，出现「回到底部」。重新渲染不改变你正在看的位置。

### 6.6 观感取值

| 项 | 取值 |
| :--- | :--- |
| 回复正文 | 14px / 24px |
| 你的消息 | 14px / 22px；气泡圆角 16px，内边距 10px 14px，最大宽度为栏宽的 90% |
| 过程行 | 13px / 24px，次要文字色 |
| 失败行 | 13px / 20px，语义错误色 |
| 间距 | 过程行之间 4px；组标题到内容 8px；回复与相邻过程组 12px；回合之间 16px |
| 输入区 | 圆角 16px；文本 14px / 24px |
| 配色 | 沿用宿主的背景与文字变量和 Pith 的强调色，不改用 dsh 的蓝色 |
| 动效 | 运行中的过程行可以有微光；`prefers-reduced-motion` 下为静态 |

等待状态用 `role="status"`，失败行用 `role="alert"`，折叠控件带 `aria-expanded`。

## 7. 自适应与主题

1. **连续几何自适应（[`resolveResponsiveLayout`](../../src/plugins/stage-reader/pagination.ts)）**：按容器实时净宽、高宽比与指针类型切换右侧栏形态（`"split-right"`、`"overlay-drawer"`、`"bottom-sheet"`）与最大可读栏数（1 到 3 栏）。
2. **跟随宿主与系统主题**：统一通过宿主无关的语义变量取色，优先读 DSH 与 Obsidian 的宿主变量；独立 Web 壳用中性的系统亮暗色（Light `#ffffff / #f6f6f7`，Dark `#18181b / #202024`）。
3. 课题卡片的时间戳不折行；不调用阻塞式的 `window.alert()`。
