# 三角色协作契约（Brain · Worker · Tester）

角色拆分的唯一依据是**信息差异**：作者上下文包含“我为什么这么写”，自审必然退化为自我确认。

| 角色 | 职责 | 严禁行为 |
| :--- | :--- | :--- |
| **Brain（架构与协调）** | 定义 `docs/` 契约、冻结 `src/core/` 公共接口、编写结构化《任务包》、维护 `docs/HANDOFF.md` | 不绕过契约堆砌功能代码、不把 diff 塞进交接文档 |
| **Worker（垂直切面实现）** | 在授权目录内完成任务包实现、编写并跑通单测与类型检查（`npm run typecheck && npm test`） | **共享工作区严格串行（Write=1）**；不越权改其他插件或私改 `src/core/` 契约 |
| **Tester（独立静态与动态验收）** | 对照任务包做静态边界审查 + 真实运行环境验证，出具通过/退回/升级报告 | 不直接替 Worker 改代码，不放过未实际运行的“替身绿灯” |

## 派发铁律

1. **先冻结契约，再派发 Worker**：任何跨模块接口（`src/core/types.ts`、`host.ts`、Service 接口）由 Brain 先行定稿并通过 `typecheck`，再派发 Worker 填肉。
2. **写操作严格串行（共享工作树 Write = 1）**：同一工作树同一时刻只允许 1 个活跃 Worker 写代码；只有只读调研（如生成研究资料）或拥有独立 Git Worktree 且写文件集 100% 物理正交的两个独立 `src/plugins/<id>/` 才允许并行。
3. **每次合入必过架构门禁**：任何提交必须保持 `tests/boundaries.test.ts` 全绿，零破窗。
